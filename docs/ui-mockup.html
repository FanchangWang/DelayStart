自启动项

—

这里的「禁用」与「移出延时」都是 软禁用：不会删除注册表值，也不会移动文件，随时可以还原成系统默认状态。
本页只列出系统里已经存在的自启动项。手动添加的程序属于调度任务而非系统自启动项，只出现在「延时启动」页。

延时启动

—

延时时间是 相对登录时刻 的时间点，不是累加。同一时间点的程序按列表顺序依次发起启动。
如果 B 依赖 A 先启动，请给 B 设置 更大 的延时值 —— 只保证发起顺序，不保证 A 已完成初始化。

系统启动项

服务、驱动、登录组件的只读检查

此页仅供查看，不参与延时启动。
系统服务、内核驱动、Winlogon 组件的启动顺序由 Windows 控制。强行延时会拖慢甚至破坏系统启动，这里只做展示与安全排查。

服务的正确延时方式是改用 Windows 原生的「自动（延迟启动）」——系统启动约 2 分钟后拉起，比第三方接管更安全。

设置

DelayStart 全局配置

以下行为是固定设计，不提供开关：进入程序时自动扫描一次自启动项；关闭窗口即退出程序（不常驻托盘，开机调度由计划任务负责）。
延时启动
决定弹窗里可选的延时值，以及调度器的存活时长
预设延时选项
「延时启动」弹窗里的快捷按钮。逗号分隔，单位秒。默认 0, 5, 10, 15, 20, 30, 60
单条目延时上限
只用于输入校验，防止误填超大数值。不影响调度能力 —— 设成 1 小时、3 小时都能正常执行
全部启动完成后，进度面板保留
让用户看到「已全部启动」的结果，之后调度器自动退出
启动失败时重试
预计调度器驻留时长 自动计算
= 最长延时（当前 60 秒）+ 面板保留（3 秒）+ 启动开销。 调度器会在最后一项启动后自动退出，不会常驻后台。
约 1 分 10 秒
启动方式
影响目标程序能否正常工作
普通用户程序优先降权启动
使用 CreateProcessAsUser 以当前登录用户身份启动，避免继承管理员权限导致拖拽、剪贴板、文件权限异常
降权失败时回退为直接启动
宁可启动成管理员，也不要启动失败
